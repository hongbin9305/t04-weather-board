## 1. T06에서 T07으로

T06의 계획/할 일/실행 기록/계획 변경 이력/완료 기록을 본인의 T07 계정 소유 자료로 이전했다. T07에는 별도 소유자 컬럼을 추가했으며, T06 테이블은 삭제하지 않았다. 기존 공개 접근 경로는 보안을 위해 권한을 철회했으므로 T06 공개 원본 앱의 예전 읽기/쓰기 동작에는 제한이 있다.

## 2. 가입과 로그인, 암호 저장

Supabase Auth 이메일 + 비밀번호 인증, 가입 확인 메일, 로그인, 로그아웃을 사용한다. 비밀번호 직접 DB 저장 방식을 폐기하고 인증 플랫폼의 해시 저장을 사용한다. 길이 8자 이상을 요청하고 로그인 실패 시 이메일 존재 여부를 구분하지 않는 메시지를 보여준다. 비밀번호, 전체 암호 해시, JWT 또는 비밀 키를 저장소나 이 설명서에 첨부하지 않는다.

## 3. 로그인 상태와 서버 요청

프런트엔드는 Supabase Auth 세션을 이용해 `Authorization: Bearer` 헤더로 `/api/records`에 요청한다. 서버는 `/auth/v1/user`로 사용자 확인 후 소유자 ID를 서버에서 지정하고 PostgREST의 사용자 RLS를 통과시킨다. DB의 `pds07_active_session()`은 세션 ID가 실제 `auth.sessions`에 유효하게 존재하는지도 확인하도록 설계했다. 비로그인 기록은 UI에 표시하지 않는다. 소스 경로: `app.js`, `diary.js`, `api/records.js`.

## 4. 다른 계정 자료 격리

7개 `pds07_*` 테이블에 RLS를 적용하고 `owner_id = auth.uid()` 및 활성 세션 확인을 검사한다. 부모 계획/할 일에 소유권을 확인하는 트리거를 사용한다. 유효한 A/B 각 계정의 DB 역할 및 세션 클레임 기반 교차 시험: 양 방향 타인 계획 SELECT/UPDATE/DELETE 각 0행, 자기 계획은 A 3건/B 1건만 표시됨. 익명 DB 역할은 SELECT 권한 오류(42501). 시험은 트랜잭션 ROLLBACK으로 종료했다. 상세 증빙: `evidence/owner-isolation-2026-10-26.md`. **HTTP 타인 자료 404 및 로그아웃 전 토큰 재사용 거부는 실측 증빙 미완료**이며 SQL 시험과 동일시하지 않는다.

## 5. 5일 실제 기록과 규칙 변경

질문: **공부 전에 과목별 목표 시간을 정하면 실제 공부 시간이 달라지는가?**
지표: 실제 공부 시간(분), KST 기준 같은 날 한 행의 분 합계.
초기 규칙: 공부할 과목을 먼저 정한다.
변경 규칙: 공부를 시작하기 전에 과목별 목표 공부 시간(분)을 미리 배분해 기록한다.

## 6. 내보내기 및 계정 삭제

로그인 상태에서 내보내기 탭에서 내 계정의 7개 자료를 JSON으로 다운로드할 수 있다. 계정 삭제는 2회 본인 확인(문구 + 최종 확인) 이후 `pds07-delete-account` Supabase Edge Function을 통해 현재 유효한 세션을 확인하고 해당 Auth 사용자 계정을 삭제하도록 구현했다. DB owner_id의 Auth FK ON DELETE CASCADE에 따라 연결 기록이 삭제된다. **사용자의 실계정은 삭제 시험하지 않았다**; 계정 삭제는 되돌릴 수 없으며 사용자 본인만 실행해야 한다.
