## A 시작 요청 원문 (B에서도 동일하게 사용)
> 기존 공개 T04 WEATHER LOG를 대상으로, 작업 전 확정한 frozen-checks.json의 10개 검사 기준을 변경하지 말고 웹앱의 상태와 검증 가능성을 개선해 주세요. 시점별 코드·검사 결과·사용 시간·요청 및 호출 수를 기록하세요. 중단 요청 시 변경하지 않은 검사 결과와 현재 상태, 다음 실행 명령, 통과·실패, 잔여 문제, 원본 버전과 변경 버전을 문서로 남기세요.

## 목표
고정 검사 10개를 모두 통과하면서 마지막 정상 데이터 보존, 오류별 상태, 합성 기록과 실제 기록 분리를 유지. AI B가 대화 내역 없이 본 문서와 저장소만으로 재개 가능해야 함.

## 실행 및 재현
1. 프로젝트 소스 `t04-weather-board-starter/` 확인.
2. 브라우저에서 `index.html` 열기 (필요 시 정적 HTTP 서버).
3. `t05/frozen-checks.json`의 입력과 기대값을 그대로 확인. 실패 fixture는 항상 reset → D1-A → D1-B → 해당 실패 순서.
4. 제출은 결과물 URL + 변경 파일 전체를 내려받을 수 있는 40자리 full commit SHA 주소. 교체 전 원본 커밋 보존.

## B 담당자의 첫 행동 (A 완료·중단 이후 실행)
1. 기존 AI A 대화 내용은 전달하지 않음.
2. **공통 최초 요청문**, `frozen-checks.json`, 본 문서와 Git 저장소를 새로운 AI B 세션에 제공.
3. AI A 종료 이후 상태로 같은 조건에서 재개, 결과를 10개 테스트로 기록.
4. 실제 사용 시간, 요청·호출 수, 통과·오류 수를 정해진 기준으로 측정하고, 동일 검사표에 채움.
5. 숨김 정보 없는 블라인드 비교표를 작성하되 누구인지 식별 가능한 모델명/서비스명은 판정 화면에서 A/B로만 표기.

## 남은 작업

- 동등한 조건의 AI B 별도 실제 세션 및 B 인수인계 접수·종료 기록
- 동일 10건의 실제 실행 회차 및 실패 건수, 차이 및 재작업량 계산
- A/B 서비스 명은 공개 비교 결과에 감춤
