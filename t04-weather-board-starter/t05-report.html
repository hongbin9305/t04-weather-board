T05 · 진행 중인 공개 보고서

대화가 끊겨도 이어지는 프로젝트

대상: 기존 T04 WEATHER LOG. 첫 번째 작업자 A가 고정 검사를 지키며 작업하고, 별도 작업자 B가 인수인계서만 받아 재개하는지를 평가합니다.

판정 현재 상태

이 보고서는 중간 기록입니다. 두 번째 AI B의 실제 재개, 같은 시간 상한, 전체 검사 및 블라인드 비교는 아직 완료되지 않았습니다.

작업 대상: WEATHER LOG · 소스 저장소 · 인수인계 문서 · 고정 검사 10개 (JSON)

고정 검사 10개 · A와 B 동일

ID시험 입력 및 기대 결과A 상태B 상태
01공개 URL 비로그인 열기확인(설정)미실행
02실제 기온·원천·시각·값 일치확인(화면)미실행
03합성 D1-A → 1행/100자동 PASS미실행
04합성 D1-B → 같은 행/105자동 PASS미실행
05합성 D2 → 2행/+15자동 PASS미실행
06TIMEOUT → stale/timeout자동 PASS미실행
07AUTH 401 → stale/auth자동 PASS미실행
08RATE 429 → stale/rate_limit자동 PASS미실행
09OFFLINE → stale/offline자동 PASS미실행
10SCHEMA BREAK → RECOVER → fresh/none자동 PASS미실행
검사는 AI A 작업 시작 전에 GitHub에 고정했습니다. A의 03~10은 Node VM 공식 합성 fixture 실행 8/8 PASS, 01~02는 화면·설정 수동 관측입니다. B는 아직 미실행입니다. 실행 근거 · 재실행 스크립트.

중단 · 인수인계 · 재개 순서

A 시작 → 검사 10개 고정 이후 작업 시작 · 최초 요청 및 기준 SHA 보존

A 중단 → 실행 결과, 중단 시 버전 SHA, 실패 상태, 첫 실행 명령, 다음 행동 문서화 [미완료]

B 재개 → 새로운 AI에 동일한 최초 요청·검사·인수인계서 제공, 기존 A 채팅 미제공 [미완료]

공정 비교 → A/B 동일 검사 10개, 같은 시간·요청·호출 상한, FAIL 횟수와 재작업량 비교 [미완료]

판정 원칙과 근거

① 어디로: 이 보고서와 소스 링크를 확인합니다. ② 행동: 고정 검사를 실행하고 각 결과를 관찰합니다. ③ 통과: 두 AI의 독립 실행 결과와 시간·요청·호출·오류 수가 일치 가능한 형식으로 남습니다. ④ 안 될 때: 누락된 결과는 미실행으로 표시하고 점수나 회차를 추정하지 않습니다.

블라인드 비교 기준: 실제 AI 이름을 감춘 A/B 표기, 동일 검사 입력, FAIL 개수, 완료 시간, 요청·호출 수, 재작업량. 완료 전에는 비교 우열을 주장하지 않습니다.
